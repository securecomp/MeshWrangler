# MeshWrangler

**Historical Mesh Network Observation & Analysis**  
*Collect. Correlate. Explore. Evaluate.*

MeshWrangler preserves and consolidates historical mesh-radio observations from multiple devices to study observed network coverage, node activity, and real-world communications utility. It initially supports database snapshots generated by the Meshtastic application on Apple iOS. The project is independent and is not affiliated with or endorsed by Meshtastic LLC or Apple Inc.

## Processing historical data

Requires Python 3 and existing working copies of device application databases. See the [compatibility matrix](docs/COMPATIBILITY.md) for tested versions. Core processing uses the Python standard library. The included `wrangle_it_v1.sh` launcher runs the three processing stages in order, records stdout/stderr, and stops on a failed stage.

Copy the six working files from `src/` into your private working copy of the Meshtastic iOS application’s `Documents/NodeBackups/` collection (an application-generated directory, not a MeshWrangler naming convention), as described in [docs/PROCESSING.md](docs/PROCESSING.md). Run `./wrangle_it_v1.sh` from that directory (or `bash wrangle_it_v1.sh` if executable permission was stripped). The equivalent individual commands are:

```bash
python3 ./meshtastic_master_export_v1.py
python3 ./meshtastic_consolidate_v2.py
python3 ./meshtastic_quality_flags_review_v1.py
```

The repository includes four current Python source utilities and does not include private snapshots or exported node data. **Privacy:** generated `exports/master_manifest.json` and `exports/master_data/reconciliation_manifest.json` record the absolute local source directory (`root` and `source_root`, respectively); these output manifests may reveal usernames or folder paths and must not be published unredacted. Work on copies of your source application data and preserve your originals independently. Generated launcher logs in `logs/` may contain absolute paths, device identifiers, and diagnostic details; `.gitignore` excludes `logs/` and `*.log` from ordinary Git staging. Review tracked files separately before publication.

## Explore the data in a browser

From the repository tree, open [`src/meshtastic_explorer.html`](src/meshtastic_explorer.html) in a compatible desktop browser. If you copied the six runnable files into your private `NodeBackups/` working collection as instructed above, you can instead open `meshtastic_explorer.html` from that working copy; both are the same Explorer file. After running the three processing stages, choose your private source collection folder (existing layout: `NodeBackups/`) in the file picker. The Explorer locates the consolidated dataset in `exports/master_data/` for inspection, filtering, mapping, and historical movement review. The HTML file is part of the repository; it is not a hosted web service.

**Explorer v0.9.12** preserves interactive Leaflet mapping in Online and Offline modes. Offline uses a dark basemap without starting new map-tile or terrain-elevation requests; it is not a guaranteed zero-network mode because library assets and requests already in progress may still use the network. Safari 26.5 acceptance covered pan, zoom, node selection/details, Fit Main/All, and online tile reloading. Earlier Explorer v0.9.11 acceptance remains documented in the compatibility history. See [Explorer instructions](explorer/EXPLORER_README.md).

Processing chosen node files is local, but the online map library, map tiles, and terrain elevation service may contact external hosts; coordinates may be sent for elevation requests. The fallback offline coordinate plot is not a downloadable regional map. Review [third-party licensing, attribution, and network privacy](THIRD_PARTY_NOTICES.md).

## Compatibility and limitations

See [Compatibility](docs/COMPATIBILITY.md) for verified versus observed/pending version information. Historical node visibility provides evidence of network activity and geographic exposure, but does not alone establish successful message delivery or end-to-end connectivity. Coverage overlays and classifications require careful interpretation.
